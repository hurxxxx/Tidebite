## 이전 수정: 몸체 없는 물고기 레벨·체력 표시

사용자 스크린샷에 다른 물고기의 몸체 없이 `LV.`와 체력 막대만 남는 현상이 있었습니다. 다음 표시 경로를 수정했습니다.

- OceanView의 고정 거리(약 33단위) 숨김 기준을 화면 비율·확대 정도·개체 크기를 반영한 뷰포트 기준으로 교체했습니다. 시뮬레이션의 현재 위치 대신 실제 표시하는 보간 위치로 판단합니다.
- 숨긴 물고기의 Transform은 마지막 표시 위치에 남아 있었는데, UI는 생존 여부만 확인해 그 위치에 이름표를 그렸습니다. `TryGetLabelPosition`으로 실제 활성화된 물고기만 이름표 위치를 제공하도록 바꾸고 UI가 이 결과를 확인합니다. 미니맵의 살아 있는 개체 표시는 유지합니다.
- 좌우 전환 때 몸체 배율을 +1에서 -1로 보간하면서 0 근처에서 그림 전체가 매우 얇아졌습니다. 방향 부호와 뱅크 두께를 분리하고 평상시 전환 두께가 82% 아래로 내려가지 않게 했습니다.
- 몸통 셰이더의 꼬리 회전·턴·급강하 휨을 포함하도록 몸체 메시 경계를 넓혀 화면 가장자리에서의 조기 컬링을 방지합니다.

`Tidebite.Editor.FishVisibilityValidation.Run`: **522개 검사 통과**. 4:3·16:9·20:9·32:9 최대 성장 뷰포트 36개 위치, 표시 후 화면 밖 이동·보간 위치 차이·사망·빈 슬롯·유효하지 않은 인덱스 6개 검사, 15/30/60/120Hz 방향 전환 480프레임을 검사했습니다. 관측한 최소 몸체 두께 배율은 **0.8245**입니다. 결과: `TestResults/fish-visibility.json`, 로그: `Logs/fish-visibility.log`.

macOS 재빌드에 성공했고, 기존 플레이어를 종료한 뒤 그래픽 프로세스 한 개로 수정 빌드를 직접 조작 가능한 솔로 모드로 다시 실행했습니다. 네이티브 화면에서 플레이어·근처 봇·화면 가장자리에 일부 보이는 큰 물고기와 이름표의 표시를 확인했습니다. 자동 조작/자동 종료 옵션은 사용하지 않았습니다. 시작 로그: `TestResults/fish-visibility-player.log`.

핵심 전투·AI·네트워크 규칙 변경은 없습니다. 위 검사는 실제 프레젠테이션과 Transform/UI 위치 제공 계약을 확인하며 전체 GPU 영상이나 모바일 실기기 검증은 아닙니다.

## 이전 수정: 배경 깜빡임·잘못된 가림 방지

바다 바닥은 불투명하고 깊이를 기록하지만 기존 위치가 y=0이어서, 같은 높이의 경계 소품은 깊이 경합이 생길 수 있고 음수 높이의 원경/군락은 바닥 뒤에 가려질 수 있었습니다. 바닥을 y=-2로 내려 모든 배경 소품과 깊이를 분리했습니다. 투명 소품 341개에는 레이어별 고정 그리기 순서를 부여해 같은 순서의 겹침도 제거했습니다.

카메라 시차가 이전에는 정점 셰이더에만 적용되어 CPU의 Renderer.bounds는 이동 전 위치에 남았습니다. 시차를 각 Transform에 적용하고 셰이더의 중복 이동을 제거해, 실제 표시 위치와 프러스텀 컬링 위치가 일치하게 했습니다. 해초의 작은 흔들림은 기존 여유 있는 메시 경계 안에 유지됩니다. 카메라 이동을 누적하지 않고 원래 배치에 시차를 더합니다.

`Tidebite.Editor.HabitatValidation.Run`을 배치 모드에서 실행했습니다. 실제 OceanView와 341개 Renderer를 생성해 13×13개 카메라 위치, 4:3·16:9·20:9 화면 비율, 시작/최대 성장 확대 정도를 조합한 **1,014조건**을 검사합니다. 모든 소품의 변형 정점이 Renderer.bounds 안에 있는지, 바닥과 깊이가 분리되는지, 정렬 순서가 겹치는지, 보이는 기하를 잘못 컬링하는 후보가 있는지 확인합니다.

- 수정 전: 검사 실패. 시차로 이동한 기하와 표시 경계가 불일치했고 잘못된 컬링 후보 2,177건이 나왔습니다. 후보는 투명한 부분을 포함한 기하 검사 결과이며 실제 화면에서 관측한 깜빡임 횟수가 아닙니다.
- 수정 후: **1,014조건 통과**, 깊이 충돌·정렬 중복·경계 불일치·잘못된 컬링 후보 모두 **0건**.
- 로그: `Logs/habitat-visibility-before.log`, `Logs/habitat-visibility-after.log`. 결과: `TestResults/habitat-visibility-before.json`, `TestResults/habitat-visibility.json`.
- macOS 재빌드 성공. 그래픽 프로세스 한 개로 **60초 자동 플레이 통과**, 정상 종료 및 `SMOKE_PASS` 확인. 결과: `TestResults/habitat-flicker-play.json`, 로그: `TestResults/habitat-flicker-play.log`.
- 네이티브 화면에서 이동 전후의 군락·원경·가장자리 전경 표시를 확인했습니다. 영상의 모든 프레임을 자동 비교한 검사는 아닙니다.
- 플레이 중 4개 10초 구간: **59.7–60.0 FPS**, p95 **17.52–17.61ms**, 최대 **33.38ms**, 25ms 초과 총 **4프레임**. 순간 지연은 남아 있으며 이 단기 macOS 측정으로 모바일/장시간 성능을 보장하지 않습니다.

이 검사는 위치·깊이·경계의 회귀 검사이며 GPU 영상 전체의 무결함이나 모바일 실기기 검증을 의미하지 않습니다. 핵심 시뮬레이션과 네트워크 프로토콜은 변경하지 않았습니다.

초기 확장 빌드에서 약 47~50 FPS가 확인되어 먹이 충돌의 정밀 계산을 이동 구간 근처로 제한했습니다. 최적화 후 홈·솔로·사망 화면을 포함한 **16개 10초 구간**에서 **59.7~60.0 FPS**, p95 **17.42~17.59ms**, 최대 **33.45ms**, 25ms 초과 총 **3프레임**을 기록했습니다. 프레임당 평균 시뮬레이션 비용은 0.338~0.478ms였습니다. 로그: `TestResults/habitat-frame-pacing.log`. 이전 결과: `TestResults/habitat-before-food-culling.log`.

실제 모바일 FPS·발열·메모리 결과가 아닙니다. 개별 전투의 피해 숫자와 모든 성장 구간을 영상으로 자동 검증하지는 않았으며, 피해·회복·성장은 위 핵심 검사로 확인했습니다. 수집한 최종 실행 로그에서 런타임 예외·직렬화 오류·셰이더 오류는 발견되지 않았습니다. 핵심 검사 로그는 `TestResults/habitat-core-tests.log`, 빌드 로그는 `Logs/build-mac.log`, `Logs/build-linux.log`입니다.

**프로토콜 1 클라이언트/서버와 호환되지 않습니다.** 체력·어종·64개체·먹이 정보가 확장되어 양쪽을 함께 갱신해야 합니다. 64비트 시야 및 확장 먹이는 직렬화 검사 범위이며, 네이티브 Linux에서 실제 UDP·장시간 부하·지연/손실 검사를 추가해야 합니다.

`TestResults/network-2-0ms/report.json`, `TestResults/network-32-0ms/report.json`에 이전 클라이언트 결과가 있습니다. 스냅샷 수는 분할 패킷 수이며 서버 틱 수와 같지 않습니다.

초기 `network-2-75ms` 실행은 Release에서 FishNet 지연 시뮬레이터가 비활성화되어 **지연/손실 검증 결과로 인정하지 않습니다**. 실제 UDP 프록시를 사용하는 `scripts/linux-smoke.py`와 `scripts/udp-proxy.py`를 마련했으며 네이티브 x86_64 Linux에서 검증해야 합니다. 프록시는 양방향 각각 75ms 지연과 3% 확률 패킷 손실을 주입합니다.

과거 32개 macOS 프로세스 검사로 Dock에 앱이 표시되어 사용자 작업을 방해했습니다. 이후 다중 macOS 검사는 `--allow-dock-apps`를 명시하지 않으면 실행되지 않도록 했습니다. 이번 작업은 그래픽 게임 앱을 한 번에 하나만 실행했습니다.
